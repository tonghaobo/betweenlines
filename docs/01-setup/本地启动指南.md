# 本地启动指南

## 前置准备：首次配置流程

如果你刚 clone 项目，按以下顺序完成首次配置：

### 1. 确认基础环境

```bash
# 检查 Node.js 版本（需要 18+）
node -v

# 检查 Python 版本（需要 3.11+）
python3 --version
```

- Node.js 未安装或版本不够 → [nvm 安装指引](https://github.com/nvm-sh/nvm)
- Python 未安装或版本不够 → [pyenv 安装指引](https://github.com/pyenv/pyenv)（推荐）或 [python.org](https://www.python.org/downloads/)

### 2. 获取豆包 API Key

1. 访问 [火山引擎 ARK 控制台](https://console.volcengine.com/ark/region:ark+cn-beijing/overview)
2. 注册/登录火山引擎账号
3. 在"推理接入" → "API Key管理"中创建 API Key
4. 格式类似 `ark-xxxxxxxxxx-xxxxx`，复制备用

### 3. 克隆项目

```bash
git clone <仓库地址> chatvibe
cd chatvibe
```

### 4. 按下方指引分别配置后端和前端

## 一、后端启动

### 1. 进入后端目录 & 创建虚拟环境

```bash
cd backend

# 创建虚拟环境（仅首次）
python3 -m venv .venv

# 激活虚拟环境（每次启动前都需要）
source .venv/bin/activate

# 确认终端提示符前面出现 (.venv)，表示已激活
```

### 2. 安装依赖

```bash
# 升级 pip（可选但推荐，避免旧版兼容问题）
pip install --upgrade pip

# 安装项目依赖（仅首次 / 依赖变更时）
pip install -r requirements.txt
```

> **故障排除**：如果遇到 `externally-managed-environment` 错误：
> - 确认已激活 `.venv` 虚拟环境（终端提示符前应有 `(.venv)`）
> - 如果 `.venv/bin/pip` 不存在，先执行 `python3 -m ensurepip --upgrade`
> - 如果 Homebrew 管理的 Python 有问题，建议用 pyenv 安装独立的 Python 3.11

### 3. 配置环境变量

创建 `backend/.env` 文件（项目首次启动时不存在此文件，需手动创建）：

```bash
# 直接用编辑器创建，或命令行创建：
cat > backend/.env << 'EOF'
OPENAI_API_KEY=替换为你的豆包API_Key（格式 ark-xxxxx）
OPENAI_MODEL=doubao-pro-32k-240615
OPENAI_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ALLOWED_ORIGINS=http://localhost:3000
EOF
```

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `OPENAI_API_KEY` | 豆包/火山引擎 API Key | **必填，替换成自己的** |
| `OPENAI_MODEL` | 文本分析模型 | `doubao-pro-32k-240615` |
| `OPENAI_BASE_URL` | API 地址 | `https://ark.cn-beijing.volces.com/api/v3` |
| `ALLOWED_ORIGINS` | CORS 允许的前端地址，逗号分隔 | `http://localhost:3000` |

> ⚠️ **重要**：`OPENAI_API_KEY` 必须替换为你自己的豆包 Key，不要使用示例值。

### 4. 启动服务

```bash
uvicorn app.main:app --reload --port 8000
```

- `--reload`：代码变更自动重启（开发用）
- `--port 8000`：监听端口

验证启动成功：

```bash
curl http://localhost:8000/health
# 返回 { "status": "healthy", ... }
```

### 5. 运行测试（可选）

```bash
python tests/test_api.py
```

## 二、前端启动

### 1. 进入前端目录 & 安装依赖

```bash
cd frontend

# 安装依赖（仅首次 / 依赖变更时）
npm install
```

### 2. 配置环境变量

创建 `frontend/.env.local` 文件（项目首次启动时不存在此文件，需手动创建）：

```bash
cat > frontend/.env.local << 'EOF'
NEXT_PUBLIC_API_URL=http://localhost:8000
EOF
```

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `NEXT_PUBLIC_API_URL` | 后端 API 地址 | `http://localhost:8000` |

> 如果后端部署在其他机器或端口，修改对应的地址即可。

### 3. 启动开发服务器

```bash
npm run dev
```

前端默认运行在 `http://localhost:3000`。

### 4. 局域网其他设备访问（可选）

如果你需要用手机或其他设备通过局域网 IP 访问前端进行测试：

```bash
# 先构建生产版本，再以生产模式启动（避免 HMR WebSocket 问题）
npm run build && npm start -- -H 0.0.0.0 -p 3000
```

然后通过 `http://<你的局域网IP>:3000` 访问，例如 `http://192.168.31.195:3000`。

> **注意**：`npm run dev` 开发模式在通过 IP 访问时，HMR WebSocket 可能握手失败导致页面交互异常。建议局域网测试使用上面的 build + start 方式。

## 四、常见问题

### Q: 首次启动后端报 `ModuleNotFoundError: No module named 'xxxx'`？

**A:** 没安装依赖或虚拟环境没激活。确认：
1. 终端提示符前有 `(.venv)`
2. 执行过 `pip install -r requirements.txt`

### Q: 截图分析报错"分析失败"？

**A:** 检查 `backend/.env` 中的 `OPENAI_API_KEY` 是否正确。如果系统环境变量里也有 `OPENAI_API_KEY`（例如全局配了 OpenAI 的 Key），项目会优先使用 `.env` 文件的值（因为 `load_dotenv(override=True)`）。

验证方式：

```bash
cd backend
source .venv/bin/activate
python -c "from app.core.config import settings; print(settings.OPENAI_API_KEY[:20])"
# 应该输出 ark- 开头，不是 sk-proj- 开头
```

### Q: 前后端通讯不通？

**A:** 确认后端 CORS 配置中的 `ALLOWED_ORIGINS` 包含了前端地址（默认 `http://localhost:3000`）。

### Q: `pip install` 报 `externally-managed-environment`？

**A:** 你没有激活虚拟环境。执行 `source .venv/bin/activate` 后再试。

### Q: 前端修改了环境变量不生效？

**A:** Next.js 的 `NEXT_PUBLIC_*` 变量在构建时注入，修改后需要重启 `npm run dev`。
