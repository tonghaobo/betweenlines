# Chat Coach（聊天教练）— 产品交付计划总览

## 一句话定位
帮用户分析聊天状态，并给出自然回复建议，避免聊天翻车。

## 项目概况

| 项目 | 内容 |
|------|------|
| 目标交付时间 | 2~4 周内上线 MVP |
| 技术栈 | Next.js (前端) + FastAPI (后端) + OpenAI API + SQLite |
| 部署 | 前端 Vercel / 后端 Railway |
| V1 核心闭环 | 粘贴聊天记录 → AI 分析 → 输出互动分析 → 给出回复建议 |
| V1 功能数量 | 3 个：聊天分析、回复建议（3 风格）、聊天节奏建议 |
| V1 页面数量 | 3 个：首页、结果页、反馈页 |

## AI 执行说明

每个步骤文件都是**自包含的**，可以直接交给 AI 执行。文件包含：
1. **明确的任务描述** — AI 可以理解要做什么
2. **具体的文件/目录路径** — AI 知道在哪里创建/修改
3. **代码示例和结构要求** — AI 知道代码长什么样
4. **验收标准** — AI 可以自检完成情况

## 执行顺序
按编号 01 → 07 顺序执行。每个文件独立执行，前一步的输出是后一步的输入。

## 技术架构图（简化）

```
用户浏览器 → Vercel (Next.js) → Railway (FastAPI) → OpenAI API
                                    ↓
                               SQLite (V1 可选)
```

## 核心约束（来自 PRD）

- ❌ 不做绝对判断（不说"她喜欢你"）
- ❌ 不代替用户聊天（不自动回复）
- ❌ 不制造焦虑（禁止 PUA 风格）
- ❌ 不训练模型（V1 直接调 API）
- ✅ 聊天记录默认不存储
- ✅ 输出必须自然、可发送
